# Blender Observer 2.0

Приложение для индексации библиотечных связей `.blend`, наблюдения за перемещениями и исправления путей. Интерфейс — PySide6 (Qt Widgets), данные — SQLite, чтение и запись `.blend` — Blendlib 1.4.4. Установка Blender для работы программы не нужна.

## Совместимость

**Только файлы Blender 2.79, 64-bit, little-endian**, включая gzip-сжатые `.blend`. Это ограничение предоставленного Blendlib. Другие версии отображаются с ошибкой чтения; приложение не пытается записывать их в обход проверки. Python 3.10+; установка зависимостей должна выполняться тем интерпретатором, которым запускается приложение.

## Установка и запуск в Windows

Распакуйте архив в отдельную папку, откройте там терминал:

```bat
python -m pip install -r requirements.txt
python app.py
```

Используется облегчённый дистрибутив `PySide6-Essentials`: он предоставляет необходимые `PySide6.QtWidgets`, `QtCore`, `QtGui`. WebEngine и Addons не нужны. SQLite входит в Python.

## Работа

1. Выберите папку проекта. Нажмите **Индексировать**. Обычная индексация пропускает файлы с неизменными `mtime_ns` и размером; **Перечитать всё** игнорирует этот кеш.
2. **Файлы**: список, число библиотек, ошибка последнего чтения. Выделение файла ограничивает вкладку зависимостей этим файлом. Двойной щелчок открывает его папку. **Все зависимости** возвращает общий список. База может содержать несколько ранее сканированных корней; полный список их объединяет.
3. **Зависимости**: владелец, исходный путь внутри `.blend`, разрешённый абсолютный путь и доступность библиотеки на момент последней проверки. Поиск фильтрует текущую вкладку по всем колонкам. Например, `Не найдена` показывает недоступные библиотеки.
4. Выделите одну или несколько связей и нажмите **Назначить библиотеку…**. Выбранный файл будет назначен всем выделенным строкам. Это создаёт задания, но пока не записывает `.blend`.
5. **Исправления**: проверьте владельцев и новые пути. Можно изменить назначение или убрать задания. Выберите нужные строки и нажмите **Применить выбранные исправления**. Ctrl+A выделяет все строки; скрытые фильтром строки не применяются.
6. **Начать наблюдение** включает Watchdog и запускает индексацию. Сначала дождитесь первоначального индексирования, затем перемещайте файлы. Для сетевых папок включите **Сетевая папка (опрос)** до запуска наблюдения.
7. **Журнал** показывает последние 1000 сообщений; полная история остаётся в базе.

Мониторинг только индексирует и готовит задания. Запись `.blend` всегда выполняется по явной команде. Наблюдение не включается автоматически при старте программы. Закрытие окна завершает программу; отдельная кнопка позволяет свернуть её в трей, если он доступен.

## Перемещения и относительные пути

Обрабатываются подтверждённые события перемещения файла и каталога, цепочки переименований, а также изменение расположения самого файла-владельца. В последнем случае программа сохраняет смысл его прежних библиотечных ссылок и предлагает пересчитать относительные пути. При записи задаются оба поля Library: относительный `name` и абсолютный `filepath`. Если относительный путь невозможен между дисками Windows, сохраняется абсолютный.

Наблюдение объединяет события с задержкой 2 секунды (максимум 10 секунд непрерывного потока) и раз в 60 секунд сверяет индекс. Перемещение между томами/сетевыми ресурсами может прийти как удаление и создание. В таком случае программа **не угадывает** соответствие по имени: назначьте библиотеку вручную. Аналогично для изменений, сделанных во время выключенного приложения. На сетевых файловых системах определение перемещений зависит от доступных идентификаторов файлов и возможностей Watchdog.

Индексируются `.blend` внутри выбранного корня. Библиотеки за его пределами отображаются как зависимости, но автоматически не обходятся рекурсивно. Символические ссылки при обходе пропускаются. Недоступный каталог делает обход неполным: старые записи не удаляются по результатам такого обхода.

## Сохранение и резервные копии

Перед применением закройте изменяемые файлы в Blender и остановите запись другими программами.

Для каждого файла программа:

- проверяет наличие новых библиотек и исходных путей в актуальном `.blend`;
- меняет все выбранные ссылки этого владельца за одно сохранение;
- сохраняет во временный файл в том же каталоге и повторно читает пути через Blendlib;
- проверяет, не изменились ли время и размер исходника во время операции;
- создаёт уникальную резервную копию `имя.blend.observer-<uuid>.bak` рядом с исходником;
- заменяет исходник через `os.replace`, обновляет SQLite и удаляет только успешно выполненные задания.

При ошибке задание сохраняется с пояснением. Сжатие gzip сохраняется. Резервные копии автоматически не удаляются. Для восстановления закройте программу и Blender, сохраните отдельно текущий файл, скопируйте нужный `.bak` на его место и выполните полную индексацию.

Атомарность относится к отдельному файлу, а не ко всей партии или общей транзакции файловой системы с SQLite. Если процесс/компьютер остановлен между заменой файла и обновлением базы, задание может остаться в очереди: проиндексируйте файл, проверьте путь и удалите уже выполненное задание. Проверка времени/размера не является блокировкой от внешней записи; сетевые ресурсы и резервные программы также могут менять файл. Во время работы программы не перемещайте файлы, которые она сейчас исправляет.

## Данные и миграция

По умолчанию база в `%LOCALAPPDATA%\BlenderObserver\observer.sqlite3`. Вне Windows — `~/.local/share/BlenderObserver/observer.sqlite3`. Храните базу локально, даже если `.blend` находятся на сетевом диске. Индекс, связи, очередь, ошибки, настройки и журнал сохраняются в SQLite. Для копирования базы завершите приложение.

Можно задать отдельную базу:

```bat
python app.py --db D:\ObserverData\observer.sqlite3
```

Блокировка Qt предотвращает одновременный запуск двух экземпляров с одной базой. Не используйте несколько баз для одновременного исправления одних и тех же файлов.

Исходный JSON сохранён без изменений в `legacy/blend_files_index.json`. Для переноса нажмите **Импорт старого JSON…** в пустой базе, затем выполните полную индексацию на исходном Windows-компьютере. Старые абсолютные пути должны оставаться актуальны. Импорт намеренно не доверяет старым отметкам времени: они не гарантируют, что библиотеки действительно читались. Этот JSON после миграции не используется как рабочее хранилище. Старый `redirectors_list.csv` не был приложен; его автоматическая миграция не реализована — назначения теперь редактируются в GUI.

## Исправления относительно исходника

- Убран циклический импорт `app ↔ files_indexing` и запуск инфраструктуры при импорте.
- Удалены глобальные изменяемые словари, фоновое управление Tk/pystray и зависимости от Excel/Pillow/plyer.
- Исправлена потеря заданий при ошибке записи и скрытое подавление исключений.
- Вместо `minversion == 270` используется проверка реальной совместимости Blendlib.
- Изменение зависимостей заменяет прежние рёбра индекса; повторная индексация не размножает связи.
- Ошибка чтения оставляет последние известные зависимости, помечая сам файл ошибкой.
- Индексация, проверка доступности библиотек и запись выполняются вне GUI-потока; файловые проверки дедуплицированы по пути библиотеки.
- Watchdog передаёт события через потокобезопасную очередь. Фоновая операция в приложении только одна.
- Остановка не обрывает запись посередине: она применяется между файлами. Закрытие во время операции просит дождаться её остановки.
- Иконка трея берётся из Qt; отсутствующий `images/logo.png` больше не мешает запуску.

## Структура

- `app.py` — точка входа и блокировка экземпляра.
- `observer/gui.py` — PySide6, фоновые задачи, таблицы и трей.
- `observer/monitor.py` — события Watchdog и режим опроса.
- `observer/service.py` — индексация, перемещения и выполнение заданий.
- `observer/blend.py` — адаптер Blendlib, проверка результата и сохранение.
- `observer/storage.py` — схема SQLite и импорт JSON.
- `observer/paths.py` — нормализация и пути Blender `//`.
